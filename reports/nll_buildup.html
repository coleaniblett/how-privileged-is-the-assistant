How the NLL asymmetry is built

Vestigial regression, NLL arm, exchange design (main run, results/capstone/). A walk-through from raw NLL to the verdict. Analysis only: no measure's code, criteria or data were changed. Generated by python -m reports.nll_buildup_analysis and python -m reports.nll_buildup_report. 2026-11-04.

What is being measured

The question is whether post-training makes a model worse at modelling the user's side of a chat than the assistant's side, beyond what it does to text in general (Shiller's "dominance": non-assistant personas degrade). Each family's post-trained checkpoint is compared with that family's own base model on the same texts.

The texts are real two-turn exchanges, a user turn plus the reply that followed it, from three corpora: oasst1 and UltraChat are the headline corpora, and WildChat is secondary (reported, not used for the verdict). There are 300 exchanges per corpus, or 100 for Gemma 4 31B. Every text is scored twice with the same tokens:

  • tagged: in its chat role, using the family's chat template (the user turn as the conversation's opener; the reply after its own user turn and the assistant opening);
  • plain: the same words as bare prose with every role tag removed (the reply follows its user text after a blank line).

Only the scored text's own tokens count, from content position 1 on. All numbers are in nats per token, the verdict's unit; bits-per-byte versions are in summary.csv. Contamination can be checked for OLMo only: Qwen3 and Gemma 4 results cannot rule out training-data overlap.

Do these numbers reproduce the analysis?

Yes, exactly. All per-text quantities come from the measure's own code (measures/vestigial_regression/analyze_exchanges.py: load_family, per_text, run, with asymmetry_ci from analyze.py), re-run with the same seed (0) and 10,000 resamples.

  • Against reports/capstone_results.json: 105 nats rows (every checkpoint × corpus × quantity), largest difference in mean or CI bound 0. Verdicts are identical: yes.
  • Against the committed results/capstone/vestigial_regression/exchanges_exchange/summary.csv: largest difference 5e-07 (the CSV is written to 6 decimals).
  • Build-up identities, checked on every cell: the mean of the per-text changes equals the summary's mean; Δ FC = Δ tagged − Δ plain per text; asymmetry = mean Δ FC user − mean Δ FC reply; level difference = mean change. Largest discrepancy: 2e-15 (floating point).

The CIs on the levels (Steps 0 and 1) and on the robustness versions are new. They use a separate random stream, so the measure's own numbers are unaffected.

The steps

Step 0 · Raw NLL. Negative log-likelihood is how surprised the model is by each actual next token, −log p(token | everything before it), here averaged over the text's tokens from position 1 on. Lower means the model predicts the text better. NLL(text, framing, model) = mean over positions t ≥ 1 of −ln pmodel(xt | x<t) Four conditions per exchange: user turn tagged, user turn plain, reply tagged, reply plain. Each is scored at base and at the checkpoint. Read it as a level: higher is worse.
Step 1 · Frame cost. How much the role tag helps or hurts the model predict the same words. FC = NLL(tagged) − NLL(plain), per text, at base and at the checkpoint Negative: the tag helps (the words are easier in their role). Positive: the tag hurts. It is relative: FC can fall because tagged got better, or because plain got worse by more.
Step 2 · Change from base. What post-training did to the tag's effect. ΔFC = FC(checkpoint) − FC(base), paired per text ( = ΔNLL(tagged) − ΔNLL(plain) ) Positive: post-training made this role's tag more costly (or less helpful). Negative: it made the tag more helpful.
Step 3 · Asymmetry. Whether the user's role lost more than the assistant's role. A = mean ΔFC(user turns) − mean ΔFC(replies), within a corpus The 95% CI comes from 10,000 bootstrap resamples, with the user set and the reply set resampled independently, as the analysis does (each term is paired per exchange across checkpoints). Positive: the user tag got relatively worse, which is vestigial regression. Negative: the assistant tag got relatively worse.
Step 4 · Verdict. fires ⇔ A ≥ 0.05 nats and 95% CI lower bound > 0, in both oasst1 and UltraChat 0.05 nats is the smallest effect the project counts (config.MIN_EFFECT_NATS). WildChat is reported but does not enter the verdict. "Negative in both" (A ≤ −0.05 with the CI below zero in both headline corpora) is reported as the opposite of regression; it does not fire.

Worked examples (oasst1)

Gemma 4 31B IT: positive

The user tag becomes costly while the assistant tag helps relative to plain. This is the one checkpoint that fires. oasst1, 100 user turns and 100 replies. The whole chain in one block (means, nats/token):

Qwen3-8B IT: null by cancellation

Both sides' frame costs rise by similar amounts, so their difference is about zero. oasst1, 300 user turns and 300 replies. The whole chain in one block (means, nats/token):

Two things the table makes visible. First, at OLMo DPO and Instruct, the reply side's tagged NLL roughly doubles while its plain NLL rises about half as much, and this drives the negative asymmetry everywhere. Second, OLMo's WildChat user turns get easier after post-training at every stage (tagged and plain both fall), unlike oasst1 and UltraChat. This fits OLMo's SFT data containing most of WildChat: the filter removed exact matches only, so close relatives of these texts were likely seen in training. It is one reason WildChat is secondary.

Robustness: does the verdict depend on the plain reference?

Frame cost subtracts plain-text NLL, so a verdict could in principle come from plain text moving rather than from anything about the roles. Two alternative versions, using the same independent bootstrap as the measure:

  • tagged-only: Δ user tagged − Δ reply tagged (ignores plain text);
  • plain-only: Δ user plain − Δ reply plain (ignores the tags; shown with its two inputs, since plain text moves a lot for Gemma).

They are linked exactly: frame-cost asymmetry = tagged-only − plain-only.

No fires/does-not-fire verdict changes. Gemma 4 31B IT fires on both versions; tagged-only is even larger (about +7.3) because user plain text also degrades heavily (+5.2), and the measure subtracts that. Every other checkpoint does not fire on either version. One description changes: Qwen3-8B IT's null becomes "negative in both headline corpora" on tagged-only (about −0.19 and −0.16), because its replies' tagged NLL rose more than its user turns' did. Under frame cost that difference is cancelled by replies' plain NLL also rising more, so the measure's null depends on the plain reference. OLMo SFT shows a small positive tagged-only effect in UltraChat (+0.044 [+0.023, +0.065]), with the CI above zero but the mean below the 0.05 floor, so it does not fire.

Caveats for reading these numbers

  • Off-policy replies. Every reply was written by someone else (a human or another model). A post-trained model that has its own style finds others' replies surprising, which inflates reply tagged NLL. This is the main suspect for OLMo DPO and Instruct's reply side.
  • Gemma's levels. Gemma 4 31B IT's user tagged NLL of about 11 nats/token, and plain NLL of about 8, are very high: the IT model degrades on everything that is not its own reply. The asymmetry is still clear, but it sits on top of a large general degradation (the plain-only row), which the project refers to the overgeneralization measure.
  • Contamination can be checked for OLMo only. OLMo NLL verdicts are not blind: the criteria were revised after pilot results (measures/vestigial_regression/README.md).
  • This report covers the NLL arm only. The judge arm and logit distortion are in reports/capstone_results.html.
